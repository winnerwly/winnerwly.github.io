# Trae Skill 系统：让 AI 更懂你的需求

在上一篇文章中我们介绍了 Trae AI 的基本用法，今天我们来深入聊聊 Trae 中一个非常核心的设计——**Skill 系统**。理解了 Skill，你才能真正用好 Trae 的强大能力。

## Skill 到底是什么？

Skill 直译过来是「技能」，但在 Trae 中它有特定的含义：

> **Skill = 预先定义好的、专门处理某一类任务的能力模块**

这个设计其实很符合面向对象设计中的「单一职责原则」：一件事，交给专门擅长这件事的 Skill 去做，比让一个通用 AI 处理所有事情效果更好。

我们从代码设计的角度来看一看这个概念：

```typescript
// 这就是 Skill 最本质的抽象
interface Skill {
  name: string;
  description: string;
  execute(context: TaskContext): Promise<Result>;
}
```

每个 Skill 只专注做好一件事：
- `search` Skill 擅长搜索代码库
- `ask` Skill 擅长帮你询问代码设计问题
- `prompt-analysis` Skill 擅长分析提示词模式

当你输入一个问题，Trae 会根据问题类型自动选择最合适的 Skill 来处理。这就是 Skill 系统的威力。

## 为什么需要 Skill 系统？

可能你会问：现在 AI 这么强，直接让大模型处理不就行了？为什么还要分 Skill？

原因其实很简单：**术业有专攻**。

| 对比维度 | 通用 AI 直接处理 | 专用 Skill 模块 |
|---------|----------------|---------------|
| 上下文利用 | 可能漏掉项目特定信息 | 可以针对性收集信息 |
| 处理流程 | 比较随意，全看模型发挥 | 有固定的最佳实践流程 |
| 结果稳定性 | 波动大 | 更稳定可控 |
| 可迭代优化 | 不好针对性优化 | 可以单独优化每个 Skill |
| 可扩展性 | 新增能力需要改核心逻辑 | 新增 Skill 就可以 |

举个例子：搜索代码这件事，通用 AI 可能不知道该用什么关键词，也不知道你的代码目录结构。但`search` Skill 知道用什么工具（ripgrep）、怎么索引、怎么返回最相关的结果，这些都是经过优化的。

## Trae 内置 Skill 详解

让我们看看 Trae 都内置了哪些 Skill，以及什么时候该用它们。

### 1. search - 代码搜索专家

**用途**：在你的代码库中搜索相关代码，帮助 AI 理解现有代码结构。

**什么时候触发**：
- 当你问「这个项目哪里处理了认证？」
- 当你想修改某个功能，AI 需要先找到相关代码
- 当你问「项目里是谁写的这个模块？」

**工作流程**：
1. 分析你的问题，提取关键词
2. 在代码库中进行模糊搜索和精确搜索
3. 返回最相关的代码片段给 AI
4. AI 基于这些代码回答你的问题

**使用技巧**：如果你发现 AI 找不到相关代码，可以明确说「用 search 帮我找找项目中哪里用到了 XXX」。

### 2. ask - 代码设计问答

**用途**：就像询问原开发者一样，让 AI 帮你问关于代码设计的问题。

**什么时候触发**：
- 当你看不懂一段代码为什么这么写
- 当你想理解某个设计决策的原因
- 当你在看遗留代码，文档不全

**举个例子**：
```
你打开一段老代码，看到一个奇怪的判断。你可以说：
> ask 这段代码为什么要这么写？当时的设计考虑是什么？
```

Skill 会帮你从上下文、git 历史等多个角度分析，给出一个合理的解释。

### 3. git-ai-search - 对话历史搜索

**用途**：从 git 历史中恢复之前和 AI 对话的上下文。

**什么时候触发**：
- 你之前和 AI 讨论过某个功能，隔了几天再回来继续做
- 你想看看之前是怎么实现某个功能的
- 团队协作中，看看同事之前和 AI 聊了什么

**背后原理**：Trae 会把对话相关信息和 commit 关联起来，需要的时候可以恢复上下文。这个功能对于长时间开发大型项目特别有用。

### 4. prompt-analysis - 提示词模式分析

**用途**：分析你的提示词使用习惯，帮你提高写 prompt 的水平。

**什么时候有用**：
- 你发现 AI 经常理解错你的需求
- 你想改进自己提问的方式
- 想看看有没有更高效的提问模式

这个 Skill 会定期分析你的对话，给你改进建议。

### 5. 还有更多...

Trae 还有很多其他内置 Skill，比如：
- 代码审查相关 Skill
- 架构设计相关 Skill
- 性能分析相关 Skill

随着版本更新，Skill 列表会越来越丰富。

## Skill 系统的设计思想

如果你对软件工程设计感兴趣，Skill 这个模式其实很值得学习。

### 组合胜过继承

Skill 系统用的就是「组合」思想：一个 Agent 可以挂载任意多个 Skill，而不是通过继承来增加能力。

```typescript
// 不好的方式：继承层级越深越难维护
class BaseAgent { ... }
class SearchAgent extends BaseAgent { ... }
class CodeReviewAgent extends SearchAgent { ... }

// 好的方式：组合 Skill
class Agent {
  private skills: Skill[] = [];
  
  addSkill(skill: Skill) {
    this.skills.push(skill);
  }
  
  async execute(task: Task) {
    // 选择合适的 Skill 执行
    const skill = this.selectSkill(task);
    return skill.execute(task);
  }
}
```

这就是「组合优于继承」设计原则的典型应用。

### 开闭原则

新增能力只需要加新的 Skill，不需要改核心调度逻辑，符合「对扩展开放，对修改关闭」。

### 单一职责

每个 Skill 只做一件事，做好一件事。好维护，也好测试。

## 什么时候该用哪个 Skill？

给大家整理了一个决策表：

| 你的问题 | 该用什么 Skill |
|---------|--------------|
| 项目里哪里有 XXX 代码？ | search |
| 这段代码为什么这么设计？ | ask |
| 我之前聊到哪了？恢复一下上下文 | git-ai-search |
| 帮我看看我写的 prompt 有什么问题？ | prompt-analysis |
| 帮我 review 这段代码 | code-reviewer (代理) |
| 帮我设计一下前端架构 | frontend-architect (代理) |

其实大多数情况下 Trae 会自动帮你选，你不用手动指定。但遇到问题时，手动指定更精准。

## 自定义 Skill 开发入门

如果你需要，Trae 也支持自定义 Skill。虽然这是进阶用法，但我们可以快速了解一下。

### 什么时候需要自定义 Skill？

- 你的团队有特定的代码规范，需要专门检查
- 你有特定的文档模板生成需求
- 你想集成内部工具

### 开发一个简单 Skill 的基本结构

```typescript
// 这是一个检查代码 TODO 注释的 Skill 示例
import type { Skill, TaskContext } from "trae:skill";

export default class TodoCheckSkill implements Skill {
  name = "todo-check";
  description = "检查代码中未完成的 TODO 注释";
  
  async execute(ctx: TaskContext): Promise<Result> {
    // 1. 获取当前打开的文件
    const file = ctx.getCurrentFile();
    
    // 2. 搜索所有 TODO 注释
    const todos = this.findTodos(file.content);
    
    // 3. 返回结果给用户
    return {
      success: true,
      data: todos,
      message: `找到 ${todos.length} 个未完成的 TODO`
    };
  }
  
  private findTodos(content: string): string[] {
    const todoRegex = /\/\/\s*TODO\s*:(.*)/g;
    const matches = [];
    let match;
    while ((match = todoRegex.exec(content)) !== null) {
      matches.push(match[1].trim());
    }
    return matches;
  }
}
```

大体就是这样，具体可以看 Trae 官方文档。

## 使用 Skill 的实践技巧

最后分享几个我用下来的经验：

### 1. 善用 Skill 比靠 AI 瞎蒙更高效

遇到问题先想想：有没有专门的 Skill 处理这个？比如找代码就用 search，比让 AI 瞎猜强多了。

### 2. 复杂问题分解成多个 Skill 分步处理

比如你想重构一个模块：
1. 先用 search 找到所有相关代码
2. 再用 ask 理解原有设计
3. 最后让架构师代理帮你设计重构方案

### 3. 手动指定 Skill 更精准

如果你发现 AI 选不对，可以手动说「用 search Skill 帮我找...」，明确指定比让 AI 猜好。

### 4. 关注更新，体验新 Skill

Trae 更新挺快的，经常会加新 Skill，没事可以看看更新日志。

## 总结

Skill 系统是 Trae 区别于其他 AI 编辑器的一个核心设计。它的本质就是：**把常见的开发任务拆解成专门化的能力模块，让专业的模块做专业的事**。

理解了这个设计思想，你就能更好地利用 Trae 的能力：
- 通用问题交给通用 AI
- 特定任务交给专用 Skill
- 需要专业领域知识交给专门代理

这种分层协作的模式，比让一个大模型搞定一切更加稳定和高效。
