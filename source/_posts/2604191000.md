# AI 编程避坑指南：这些陷阱一定要注意

AI 编程确实爽，但坑也不少。我踩过的坑，整理出来给大家避避。

## 陷阱 1：幻觉问题 —— AI 编造不存在的 API

这是最常见的坑了。

### 现象

你让 AI 写个代码，AI 说「用这个库的这个 API」，结果你去文档一查，根本没这个 API。或者更离谱，这个库都不存在，纯 AI 编的。

比如：
```
AI 告诉你：用 `lodash.deepClone` 直接深拷贝。
实际：lodash 是 `cloneDeep`，不是 `deepClone`。
```

### 为什么会这样

AI 训练的时候见过很多很多很多代码，它是根据概率拼出来的，记不清具体叫什么名字，很正常。

### 怎么破

1. **凡是 AI 说的 API，你不确定，一定要去官方文档确认一下**
2. **运行一下，错了就是错了，把错误信息贴给 AI，它一般能自己改好**
3. **优先用你项目已经在用的 API，让 AI 跟着项目现有的写法走，不要乱引入新东西**

**我的经验：对于不常见的第三方库 API，AI 记错名字概率挺高的，一定要验证。**

## 陷阱 2：依赖地狱 —— AI 悄悄给你加一堆没用的依赖

### 现象

你让 AI 写一个小功能，结果一看 `package.json`，AI 给你加了五六个依赖。其实根本不需要。

比如：你就是要个正则验证邮箱，AI 给你装个 `validator.js`。其实手写正则两行代码的事。

### 为什么会这样

AI 觉得「能用第三方库就用第三方库」，它不想手写。而且它不知道你的项目已经有什么依赖，反正加就完了。

### 怎么破

- **提前说清楚**：在 prompt 里加上「不要引入不必要的依赖，能用原生实现就原生实现」
- **review 时候看一眼 `package.json`，没用的依赖删掉就行**
- **如果项目已经有某个功能的库了，告诉 AI：「我们已经用了 A 库，不要用 B 库」

## 陷阱 3：安全问题 —— AI 生成的代码可能有漏洞

这个非常重要。

### 常见安全坑

AI 生成代码时，经常会：

1. **SQL 注入**：拼接 SQL，不用参数绑定
   ```javascript
   // ❌ AI 可能写出这种代码
   const sql = `SELECT * FROM users WHERE id = ${userId}`;
   
   // ✅ 应该用参数绑定
   const sql = 'SELECT * FROM users WHERE id = ?';
   ```

2. **XSS 跨站脚本**：直接把用户输入插入 HTML，不转义
3. **硬编码密钥**：API Key、密码直接写在代码里
4. **权限检查漏掉**：这个接口不需要认证，AI 忘了加权限校验

### 怎么破

写完代码，一定要问 AI 一句：

```
帮我检查一下这段代码有没有安全漏洞，比如 SQL 注入、XSS、权限问题之类。
```

大部分时候 AI 自己就能找出来。人再抽查一下关键地方，心里有数。

## 陷阱 4：过度生成 —— 简单问题搞出一堆冗余代码

### 现象

你要一个简单的函数，AI 给你整出一个十多个文件的框架来。

比如：
- 你要：写个函数验证手机号
- AI 给你：建了个 `utils/` 目录，加了验证器类，加了错误码枚举，加了单元测试...

其实你就要个函数啊！

### 为什么会这样

AI 倾向于「设计过度，因为它觉得「这样更专业」，但很多时候你真的不需要那么复杂。

### 怎么破

- **说清楚范围：这就是个小功能，保持简单，不要过度设计**
- **如果生成过度了，直接说：「简化一下，我就要一个简单函数就行**

## 陷阱 5：理解偏差 —— 你要 A，它给你 B

### 现象

你说：帮我给这个按钮加个点击事件，跳转去首页。

AI 改完了，它给你加了个表单提交。根本不是你要的。

### 为什么会这样

- 你说的太模糊了
- AI 理解错了上下文

### 怎么破

**坏例子：**
```
这里不对，改一下。
```

**好例子：**
```
我想要的是：点击按钮后，用 window.location.href 跳转到 /home 页面。
不是表单提交，请改一下。
```

**说清楚具体哪里错了，要改成什么样，AI 很快就能改对。**

## 陷阱 6：复制粘贴 —— AI 重复代码

### 现象

你让 AI 在 A 文件加个功能，AI 把 B 文件里的一段代码又抄了一遍，完全重复。

### 为什么会这样

AI 看不到你的整个项目，它只看到当前文件，不知道你已经写过了。

### 怎么破

你要告诉它：「这个功能我们已经在 B 文件写过了，你直接导入用就行，不要重复实现。

## 陷阱 7：调试困难 —— AI 也解决不了的 bug 该怎么办

### 现象

你遇到一个诡异 bug，把错误日志给 AI，AI 瞎给方案，试了都不对。

### 这时候该怎么办

不要硬坑 AI 了，换个思路：

1. **缩小范围：** 「这个 bug 只有在什么情况下出现，你帮我分析可能哪些原因会导致这个现象？
2. **二分法：** 让 AI 帮你想几个排查步骤，你一步步试
3. **Google/Stack Overflow：** 诡异问题 AI 搞不定，还是得搜
4. **最后：** 搜到答案了，让 AI 帮你解释为什么错，帮你改

AI 不是神，它也有不知道的，该搜还是得搜。

## 陷阱 8：忘记处理错误 —— 只有成功路径，没有失败路径

### 现象

AI 生成的代码：

```javascript
// 成功路径写了，但是网络错了怎么办？数据库错了怎么办？AI 忘了处理。
async function getUser(req, res) {
  const user = await db.findUser(req.params.id);
  res.json(user);
}
```

没处理：
- 如果找不到 user，返回 404 了吗？
- 如果数据库抛异常，捕获了吗？
- 参数不对，返回 400 了吗？

### 怎么破

你得提醒 AI：

```
别忘了加错误处理，参数校验、404、异常捕获都加上。
```

## 陷阱 9：依赖版本冲突 —— AI 推荐的版本和你项目不兼容

### 现象

项目用的是 React 17，AI 给你写了一堆 React 18 的新 API。跑不起来。

### 怎么破

**提前说清楚版本！**

```
我们项目用 React 17，不要用 React 18 的新特性，请按照 React 17 写法来写。
```

## 陷阱 10：过度依赖 —— 新手容易犯，什么都让 AI 写，自己不动脑子

### 现象

刚学编程，遇到问题直接扔给 AI，AI 写完了，你也看懂，直接复制粘贴。

过了半年，你还是什么都不会，离开 AI 就写不了代码。

### 我的建议

- **新手更要**：写完 AI 写了代码，你要**逐行读懂**，不懂就问 AI「这一行干什么的？
- **理解了再用**，不要拿过来就跑
- **先自己想一遍思路，再看 AI 写的，对比一下差异很大**

**AI 是拐杖，不是轮椅。拐杖帮你走得更快，但是路还是要自己走。**

## 给新手总结一个避坑检查清单

写完 AI 写完代码，你过一遍这个清单：

- [ ] **幻觉检查**：API 真的存在吗？名字对吗？
- [ ] **依赖检查：有没有引入不必要的依赖？
- [ ] **安全检查**：SQL 注入？XSS？权限检查？密钥硬编码？
- [ ] **错误处理**：失败路径都处理了吗？空值呢？
- [ ] **风格一致**：和项目现有代码风格一致吗？
- [ ] **功能正确**：跑一下试试，真的能用吗？

这五步花不了两分钟，能帮你挡住大部分坑。

## 遇到坑了该什么心态

其实我想说：**有坑很正常**。AI 不是完美的，它会犯错。

我的心态是：

> AI 写错了很正常，改对了就行。反正它写 10 次对 9 次，我只改那一次，效率还是比我全自己写高啊。

不用因为 AI 写错你就不用了，会踩坑会改坑，才是正确使用 AI 的姿势。

## 总结

AI 编程坑虽然多，但大多都是有规律的：

- 幻觉记错 API → 验证一下就好
- 过度设计加依赖 → 提前说清楚保持简单
- 安全问题 → AI 帮你查一遍
- 理解偏差 → 说清楚具体要什么

记住一句话：**AI 出力，你把关。** 出了问题改就是了。踩几次坑，你就摸清楚 AI 脾气了，坑就越踩越少了。
