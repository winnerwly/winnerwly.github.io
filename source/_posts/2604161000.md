# Claude 提示词工程：让 AI 输出精准结果的技巧

很多人用 Claude 的时候都遇到过这个问题：**我描述了半天，AI 输出的东西完全不是我想要的**。

问题出在哪？大多不是 Claude 不行，是你的 prompt 写得有问题。这篇文章我分享一些实战下来管用的提示词技巧，帮你让 Claude 输出更符合预期。

## Claude 3.5/4 的特点

先说说 Claude 本身的特点，了解了模型特点，才能写出适合它的 prompt：

**Claude 擅长什么**：
- 超长上下文，能读懂大段代码和文档
- 逻辑推理比较严谨
- 遵循指令的能力不错
- 输出格式比较稳定

**Claude 不擅长什么**：
- 如果你说得太模糊，它也会瞎编
- 上下文装不下了性能就下降
- 特别前沿的技术知识可能过时

好消息是：只要你 prompt 写得清楚，Claude 遵循指令的能力真的不错。

## 好的 prompt 长什么样？

我总结一个好 prompt 最少要有这几个要素：

### 1. **背景信息** —— 告诉 Claude 现在是什么情况

### 2. **具体任务** —— 你到底想要它做什么

### 3. **约束条件** —— 哪些不能做，要遵守什么规则

### 4. **输出要求** —— 希望它用什么格式输出

我们来看个例子对比：

**❌ 不好的 prompt**：
```
帮我写一个验证函数。
```

问题：什么验证？验证什么？在哪里用？什么语言？什么格式输出？全靠 Claude 猜。

**✅ 好的 prompt**：
```
背景：我在写一个 Node.js 项目，需要验证用户注册的邮箱。

任务：帮我写一个邮箱验证函数 isEmailValid。

约束：
- 使用 JavaScript
- 不要用第三方库，只用原生正则
- 需要处理空值情况
- 函数返回布尔值

输出要求：
- 给出完整代码
- 加少量注释说明关键逻辑
- 最后说一下测试用例怎么写
```

你看，信息给全了，Claude 很难出错。

## 常见坏案例分析

我们看看新手常犯的几个错误，你有没有中枪？

### 坏案例 1：问题太宽泛

```
帮我看看这个 bug 怎么修。
```

**问题**：哪个 bug？在哪？错误日志呢？上下文呢？

**改**：
```
我在实现用户注册的时候，点击提交按钮后页面没反应，控制台报这个错：

Uncaught TypeError: Cannot read property 'email' of null
代码在这里：[贴代码]

帮我看看问题在哪，怎么修？
```

### 坏案例 2：多个问题混在一起

```
帮我看看这个项目结构对不对，然后写个注册接口，再帮我看看数据库密码放在哪比较安全，对了还要帮我写个 Dockerfile。
```

**问题**：一次问太多，Claude 容易漏，而且上下文用得快。

**改**：拆分一下，一个问题一个问题来。先看项目结构，没问题再写注册接口，依次来。

### 坏案例 3：模糊不清的描述

```
帮我优化一下这段代码，让它更好。
```

**问题**：「更好」是指什么？更快？更易读？更少代码？

**改**：
```
帮我优化这段代码：
1. 减少嵌套层级
2. 增加变量名可读性
3. 添加必要的注释
保持功能不变。
```

### 坏案例 4：不给示例，让 AI 猜风格

```
帮我写一篇关于 AI 的文章。

发吧。
```

**问题**：你要什么风格？多长？给个示例会死吗？

**改**：
```
帮我写一篇 500 字左右的公众号文章，主题是「AI 时代开发者该怎么学习」。
风格像这样：[放个你喜欢的示例]
要求：口语化，分小标题，结尾有总结。
```

## 常用场景提示词模板

我整理几个编程中常用场景的模板，你可以直接拿去用。

### 模板 1：代码生成

```
背景：
项目：[一句话说清楚什么项目]
语言/框架：[比如 JavaScript + React]
现有代码：[如果相关的话贴一下]

任务：
帮我生成 [具体功能，比如一个验证手机号的函数]

要求/约束：
- 遵守什么编码规范？
- 不能用什么依赖？
- 需要处理什么边界情况？
- 需要错误处理吗？

输出：
- 完整代码
- 简单说明每个部分做什么
```

### 模板 2：Debug 排错

```
我遇到一个问题：[一句话说清楚现象]

环境信息：
- 语言版本：Node.js 18
- 依赖版本：React 18
- 操作系统：Windows 11

错误信息：
[粘贴完整错误日志，或者截图描述]

相关代码：
[粘贴相关代码片段]

我的排查：
我已经试过 [说一下你试过什么方法]，还是没解决。

请帮我：
1. 分析可能是什么原因
2. 给出修复方案
3. 说明为什么会出这个问题
```

### 模板 3：代码重构

```
请帮我重构这段代码：
[粘贴代码]

重构目标：
- [ ] 提升可读性
- [ ] 提升性能
- [ ] 减少重复代码
- [ ] 符合最新 ES6+ 语法
- [ ] 添加类型标注

保持现有功能不变，不要改业务逻辑。
重构完请说明：
- 你做了哪些改动
- 为什么这么改
```

### 模板 4：代码审查

```
请帮我 review 这段代码：
[代码]

请从这几个方面检查：
1. 有没有功能性 bug
2. 有没有安全问题（比如注入、XSS 之类）
3. 有没有性能问题
4. 命名和代码风格是否清晰
5. 有什么可以改进的地方

请按优先级列出问题，给出修改建议。
```

### 模板 5：理解遗留代码

```
请帮我理解这段代码是做什么的：
[代码]

请用中文解释：
1. 这个函数/模块整体功能是什么
2. 输入输出分别是什么
3. 核心逻辑流程是怎样的
4. 有什么边界情况需要注意
5. 有没有什么隐藏的坑？
```

这些模板套进去用，效果比你自由发挥好很多。

## 上下文管理技巧

Claude 虽然上下文大，但也不是无限的。大项目开发，怎么管理上下文？

### 技巧 1：一次只聚焦一个问题

不要一开对话就把整个项目丢进去。先搜索，找到相关文件，再把相关文件内容给 Claude，这样最省上下文。

### 技巧 2：用文件引用，不要全贴

Trae 里你可以直接引用文件，不用复制粘贴全部内容，上下文省很多。

### 技巧 3：大任务拆多个对话

如果真的很大，比如重构整个模块，拆成多个对话：
1. 第一个对话：理解原有代码 + 设计方案
2. 第二个对话：逐个文件修改
3. 第三个对话：测试 + 文档

做完一个阶段，提交代码，开新对话，上下文干净。

### 技巧 4：定期开新对话

做了几个小时，上下文快满了，就开新对话。新对话重新说清楚任务，反而比上下文塞满了输出质量高。

## 思维链：让 Claude 一步步思考

Claude 支持思维链（Chain of Thought），遇到复杂问题，加上这句话效果会好很多：

```
请一步步思考，先分析问题，再给出解答。
```

这句话告诉 Claude 不要急着给答案，先理理思路。对于推理题、调试复杂 bug 特别有用。

**示例**：

```
这个函数有时候会返回 NaN，帮我找找原因：
[代码]

请一步步思考，先看看每一步计算结果可能是什么，再找出哪里可能出问题。
```

## 让 Claude 输出特定格式

有时候你需要特定格式输出，比如 JSON、Markdown 表格、代码块，一定要**明确说出来**。

**示例：要 JSON 输出**：
```
请把结果输出为严格 JSON 格式，不要加其他说明文字，不要用 markdown 代码框包裹，直接输出纯 JSON。
```

**示例：要列表输出**：
```
请用有序列表输出，每条不超过一句话。
```

**示例：要对比表格**：
```
请用 Markdown 表格对比这两个方案的优缺点。
```

Claude 挺听话的，你说清楚格式，它基本会按你说的来。

## 少即是多：该简洁的时候要简洁

不是说 prompt 越长越好，简单问题就要简洁。

**简单问题就简单说**：
```
把这段函数改成 ES6 箭头函数写法。
```

够了，不用扯一堆背景。复杂问题才需要详细背景，简单问题给一堆信息反而干扰。

## 迭代优化：不对就继续调

不要指望一次到位。AI 输出不对，很正常，继续告诉它哪里不对。

**迭代示例**：

```
你：帮我写个验证邮箱的函数。
Claude：（输出了一个函数，但是用了第三方库 validate.js）
你：我不要用第三方库，用原生正则实现就行，请重新给我一个。
Claude：（输出了原生正则版本，但是没处理空值）
你：请添加空值判断，如果输入是 null 或 undefined 返回 false。
Claude：（修正了）搞定。
```

这是正常流程，不用生气，迭代几次就对了。

## 给编程新手的几个建议

1. **宁可多说，不要少说** —— 刚开始不怕多，就怕信息不够
2. **复制粘贴错误日志** —— 全贴给 Claude，比你自己翻译一遍好
3. **给了错就指出来** —— 不用客气，直接说「这里不对，应该是 XXX」
4. **存一下好用的模板** —— 把你自己常用的prompt存起来，下次直接改改能用
5. **多试几次** —— 这次不对，调整一下说法再试，经常就对了

## 总结

提示词工程说穿了就是一句话：**把信息给足，把要求说清**。

核心原则：
- ✅ 背景信息说清楚，不要让 Claude 猜
- ✅ 任务拆解清楚，一次做一件事
- ✅ 约束条件和输出格式明确说出来
- ✅ 不对就迭代，慢慢调到你想要的
- ✅ 管理好上下文，别一次塞太满

练得多了，你自然就会摸清楚 Claude 的脾气，写出来的 prompt 越来越准，输出准确率自然就上去了。
