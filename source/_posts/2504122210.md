# 为什么选择 pnpm + monorepo？

到了 2025 年，pnpm + monorepo 已经非常成熟了。相比于多仓库分开维护，monorepo 的优势在于：

- **代码共享方便**：公共组件/工具库直接跨项目引用，不用发 npm 就能测试
- **原子提交**：一次修改可以同时更新依赖它的所有项目
- **统一工具链**：ESLint、Prettier、TypeScript 配置一份就行
- **更好的协作**：所有代码在一个仓库，Code Review 和重构都方便

而 pnpm 凭借它的硬链接机制和原生支持 workspace，已经成为目前 monorepo 的最佳选择之一。这篇文章整理了我在 2025 年的实践方案。

# 初始化结构

首先，创建基础目录结构：

```
your-project/
├── packages/          # 所有包放这里
│   ├── utils/         # 工具函数库
│   ├── components/    # 公共组件库
│   └── app/           # 主应用
├── pnpm-workspace.yaml
└── package.json
```

根目录 `pnpm-workspace.yaml` 配置：

```yaml
packages:
  - packages/*
  - internal/*
  - docs
  - .github
```

这样配置告诉 pnpm 哪些目录需要被当作 workspace 包管理。

根目录 `package.json` 推荐配置：

```json
{
  "name": "monorepo-root",
  "private": true,
  "packageManager": "pnpm@9.0.0+",
  "scripts": {
    "dev": "pnpm -r --parallel dev",
    "build": "pnpm -r build",
    "lint": "pnpm -r lint",
    "clean": "pnpm -r --parallel clean"
  }
}
```

> 💡 **private: true** 很重要，防止根目录被误 publish。

# 包之间互相引用

假如 `app` 需要依赖 `utils`，直接在 `app/package.json` 里写：

```json
{
  "name": "@your-project/app",
  "dependencies": {
    "@your-project/utils": "workspace:*"
  }
}
```

`workspace:*` 表示直接使用 workspace 里的当前版本，不用去 npm 下载。pnpm 会自动处理软链接。

如果你想固定版本，可以写成 `workspace:~` 或者具体版本号，大部分场景 `workspace:*` 够用了。

# 共享依赖怎么放？

常见的做法：

## 方案一：根目录统一管理（推荐）

```bash
pnpm add react react-dom -w
```

加上 `-w` 或者 `--workspace-root` 就是装到根目录。然后各个包不用再装一遍，直接在 `peerDependencies` 里声明：

```json
{
  "peerDependencies": {
    "react": ">=18",
    "react-dom": ">=18"
  }
}
```

优点：节省磁盘空间，所有包都用同一个版本，避免版本冲突。

## 方案二：各包自己装

如果不同包确实需要不同版本，那就各自装在自己的 `node_modules` 里。pnpo 的 hoisting 机制也能处理得很好。

# 常用命令

## 安装所有依赖

```bash
pnpm install
```

## 给特定包加依赖

```bash
pnpm add lodash --filter @your-project/utils
```

## 给所有包跑命令

```bash
pnpm -r build
pnpm -r --parallel dev
```

- `-r` 就是 `--recursive`，遍历所有包
- `--parallel` 并行执行，适合 dev 这种长时间任务

## 只跑特定包

```bash
pnpm --filter @your-project/app build
```

## 跑包 + 依赖它的包

```bash
pnpm --filter @your-project/app... build
```

三个点表示「app 及其所有依赖它的包」，重构后一次性重新构建上下游很方便。

# 版本管理与发布

如果你的包需要发布到 npm，可以用 `changesets` 这个工具，目前社区主流方案。

## 安装配置

```bash
pnpm add @changesets/cli -DW
pnpm changeset init
```

## 使用流程

1. 修改代码后，生成变更记录：

```bash
pnpm changeset
```

按照提示选择哪个包需要发布，选版本类型（major/minor/patch），写变更说明。

2. 版本升级：

```bash
pnpm changeset version
```

Changesets 会自动更新所有相关包的版本号，处理依赖之间的版本引用。

3. 发布：

```bash
pnpm changeset publish
```

配合 GitHub Actions，可以做到 merge 到 main 分支自动发布，全程不用人工操作。

# TypeScript 配置要点

## 路径别名

推荐使用 TypeScript 的 `projectReferences` 来做：

根目录 `tsconfig.json`：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@your-project/*": ["packages/*/src"]
    }
  }
}
```

各个包里面也可以配置 `projectReferences`：

```json
{
  "references": [
    { "path": "../utils" }
  ]
}
```

这样 VS Code 才能正确跳转到源码。

# Turborepo 加速构建

pnpm 本身已经很快了，如果包比较多，可以加上 Turborepo 做缓存和任务调度。

安装：

```bash
pnpm add turbo -DW
```

根目录 `turbo.json`：

```json
{
  "$schema": "https://turborepo.org/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "lint": {},
    "dev": {
      "cache": false
    }
  }
}
```

然后把脚本改成：

```json
{
  "scripts": {
    "build": "turbo run build",
    "lint": "turbo run lint"
  }
}
```

第二次构建的时候，没改的包直接用缓存，速度提升非常明显。

# .gitignore 推荐写法

```gitignore
node_modules
.pnpm-debug.log
**/dist
**/*.log
.DS_Store
```

不需要把 `pnpm-lock.yaml` 加到 ignore，反而需要提交到 git，这样所有人装依赖版本一致。

# 常见坑点

## 1. circular dependencies

pnpm 会报错提醒，这其实是好事，说明你的架构有问题。早点发现早点拆分比后面爆雷好。

## 2. peerDependencies 警告

如果根目录已经装了，但是子包还是报 peer 缺失，检查一下 hoisting 配置。大部分时候在根目录装了就没问题。

## 3. 依赖不更新

有时候改了公共包，主应用没更新。可以删掉 `node_modules` 和 `pnpm-lock.yaml` 重新 `pnpm install`。

# 2025 年推荐工具链

| 工具 | 用途 |
|------|------|
| pnpm | 包管理 |
| changesets | 版本管理与发布 |
| Turborepo | 构建缓存加速 |
| TypeScript projectReferences | 类型引用 |
| Biome | 统一做 lint + format （替代 ESLint + Prettier） |

# 总结

pnpm + monorepo 到 2025 年已经非常成熟了，生态工具链也都跟得上。核心要点其实不多：

- `pnpm-workspace.yaml` 声明哪些是包
- 跨包引用用 `workspace:*`
- 共享依赖优先放根目录，peer 声明
- 发布用 changesets，自动化很省心
- 包多了加 Turborepo 加速

按照这套方案，可以满足从个人项目到中大型团队的大部分场景。
