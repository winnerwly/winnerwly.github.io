# 文章上下篇导航换行修复

## 一、变更内容

- 将文章详情页“上一篇/下一篇”导航卡片内部由纵向排列调整为横向排列。
- 禁用旧浮动布局遗留的 `::before`、`::after` 清除浮动伪元素，避免其占用 Grid 网格位置。
- 取消导航辅助文字的底部外边距，改用统一的横向间距。
- 将文章标题限制为单行展示，空间不足时沿用原有的省略号截断效果，避免卡片高度被长标题撑开。
- 保留移动端导航卡片上下堆叠的现有响应式行为。

## 二、问题原因

问题由两层旧样式叠加造成：

- `.article-nav` 覆盖样式为导航链接设置了 `flex-direction: column`，并将标题的 `white-space` 设置为 `normal`，导致辅助文字与文章标题换行。
- 基础 `.post-nav` 样式生成了用于旧浮动布局的 `::before`、`::after` 清除浮动伪元素；切换为 Grid 后，这两个伪元素仍会作为网格项占位，导致上一篇位于右上、下一篇位于左下，形成对角线布局。

## 三、影响范围

- 影响所有带上一篇或下一篇入口的文章详情页。
- 不修改文章导航的 HTML 结构、链接地址与排序逻辑。
- 不影响首页、归档页和独立页面。

## 四、验证结果

- 桌面端：“上一篇/下一篇”和对应文章标题保持同一行。
- 桌面端：上一篇与下一篇卡片位于同一行，不再出现对角线错位。
- 长标题：空间不足时显示省略号，不产生额外换行。
- 移动端：上一篇与下一篇卡片仍按单列上下排列。
- 浏览器验证：在 `1222 × 1272` 视口下，两张卡片的纵向坐标一致，导航高度由异常状态的 `286px` 恢复为 `136px`；两个清除浮动伪元素均为 `display: none`。
- 构建验证：执行 `npm.cmd run build` 成功，共生成 262 个文件。
