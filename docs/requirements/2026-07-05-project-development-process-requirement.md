# 项目开发流程要求落地

## 一、需求背景

用户要求将项目开发流程固化为强制规则，确保所有需求、新功能、问题修复、页面改造、接口改动、配置变更、架构优化等事项，都必须遵循“先分析、再文档、经确认、后开发、再总结”的流程。

当前项目已有 `AGENTS.md` 和 `docs/README.md`，但流程要求还不够完整，且存在英文文档内容，不满足“所有开发相关文档必须统一使用中文编写”的新要求。

## 二、需求目标

将用户提供的完整流程要求写入项目规范，形成所有贡献者和 AI 编码工具必须遵守的项目级规则。

目标包括：

- 明确所有开发事项必须先写中文开发文档。
- 明确开发文档必须统一存放在 `docs` 目录。
- 明确推荐目录结构为 `docs/requirements/`、`docs/changes/`、`docs/reviews/`。
- 明确未经确认不得进入开发。
- 明确开发完成后必须输出中文开发总结。
- 明确未确认、非中文、无总结均不视为有效交付。

## 三、需求范围

### 3.1 本次包含

- 更新 `AGENTS.md`，写入完整项目开发流程要求。
- 更新 `docs/README.md`，说明文档目录、中文要求、确认机制和总结要求。
- 保留并使用 `docs/requirements/`、`docs/changes/`、`docs/reviews/` 目录结构。
- 将本次总结写入 `docs/reviews/`。

### 3.2 本次不包含

- 不修改业务代码、主题代码、页面样式或构建配置。
- 不调整历史博客文章内容。
- 不处理当前工作区中已有的其他改动，如 `DESIGN.md` 删除状态和主题模板改动。

## 四、现状分析

当前相关文件如下：

- `AGENTS.md`：已有基础仓库指南，并新增过简化版强制开发流程，但内容不如用户本次提供的规则完整。
- `docs/README.md`：当前说明较简略，且此前为英文，需要改为中文。
- `docs/2026-07-05-documents-must-use-chinese.md`：此前为“文档必须中文”的临时需求文档，位于 `docs` 根目录，不符合用户新推荐目录结构；本次不强制迁移历史文档，避免扩大范围。

本次应以用户提供的完整规则为准，覆盖旧的简化说明。

## 五、技术方案

采用纯文档变更方式完成：

- 在 `AGENTS.md` 中写入完整的中文“项目开发流程要求”章节。
- 在 `docs/README.md` 中补充中文说明，明确目录用途：
  - `docs/requirements/`：需求分析与开发前确认文档。
  - `docs/changes/`：变更说明、技术方案补充、过程调整记录。
  - `docs/reviews/`：开发完成后的总结和回顾。

## 六、影响范围

## 七、风险评估

- 如果规则写得过于简略，后续执行时可能出现解释空间，因此应尽量使用用户提供的完整规则。
- 如果直接替换过多已有内容，可能影响原有仓库指南结构，因此应在保留必要仓库信息的基础上强化流程要求。
- 文档中可保留少量技术英文，不应误判为违反中文文档要求。
