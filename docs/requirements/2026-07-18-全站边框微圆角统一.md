# 全站边框微圆角统一开发文档

## 需求名称

全站边框微圆角统一

## 一、需求背景

当前博客已经完成首页、顶部导航、归档、分类、标签、关于、相册、友链、文章详情和分页器等多轮视觉优化，整体形成了深色技术博客、绿色强调色、低透明度细边框的视觉方向。但项目中的圆角规则仍不统一：一部分导航按钮和移动端控件已经使用 `9px`、`10px`、`12px`、`14px`、`999px` 或圆形圆角，首页卡片、内容面板、文章导航、目录等大量完整边框仍是直角。

用户提出“所有边框都添加一个小圆角”，并明确这是一个大需求，需要先梳理项目。该需求会影响全站公共视觉语言，不能通过全局通配选择器简单覆盖，否则可能误伤表格内部网格线、分隔线、引用左强调线、圆形头像、胶囊导航和已有特殊控件。

本次需要先建立清晰的微圆角规则，再按组件类型有边界地应用，使全站完整边框获得统一、克制的小圆角，同时保留具有结构或语义作用的特殊形状。

## 二、需求目标

本次目标：

- 为全站当前没有圆角的完整矩形边框统一增加小圆角。
- 建立可复用的微圆角变量，避免继续散落硬编码值。
- 统一首页卡片、内页容器、文章组件、标签控件和目录面板的边框语言。
- 保持现有深色、浅色主题的颜色、边框透明度和内容层级不变。
- 保持桌面端与移动端布局、交互和信息结构不变。
- 避免对纯分隔线、表格内部网格线和特殊几何形状错误应用圆角。

建议采用的核心规则：

- 新增微圆角变量 `$radius-sm = 4px`。
- 没有圆角的完整矩形边框使用 `$radius-sm`。
- 已经具有圆角的组件原则上保留现状，不在本次强制改成 `4px`。
- 圆形、胶囊形和滚动条滑块等特殊形状保留现有语义圆角。

本次不包含：

- 不修改边框颜色、粗细和透明度。
- 不重构页面布局、模板结构和交互逻辑。
- 不修改文章 Markdown 内容。
- 不新增动画、阴影、背景纹理或第三方 UI 框架。
- 不重新设计导航、分页器或卡片尺寸。
- 不提交 `public/` 等生成产物。

## 三、需求范围

### 3.1 页面范围

- 全站顶部导航与移动端菜单。
- 首页 `/`。
- 归档页 `/archives/` 及其分页页。
- 分类总览页、单分类页。
- 标签总览页、单标签页。
- 关于页 `/about/`。
- 相册页 `/ins/`。
- 友链页 `/friends/`。
- 所有文章详情页。
- 分页器和文章目录。
- 深色主题与浅色主题。

### 3.2 计划修改文件

主要修改：

- `themes/chic/source/css/custom.styl`

开发后新增：

- `docs/reviews/2026-07-18-全站边框微圆角统一总结.md`

原则上不修改 EJS 模板、JavaScript、Hexo 配置和历史基础样式文件。只有在实际开发发现 `custom.styl` 无法安全覆盖时，才重新评估范围并再次确认。

### 3.3 纳入微圆角的组件

首页与公共区域：

- 首页操作按钮 `.home-action`。
- 首页技术视觉容器 `.home-visual` 及其内部完整边框。
- 技术视觉标签、终端块、流程块。
- 首页统计块 `.home-stats > div`。
- 内容方向卡片 `.topic-card` 与编号 `.topic-index`。
- 最近文章标签 `.latest-tags em`。
- 快速入口卡片 `.site-link-card`。

通用内容与聚合页：

- 旧通用容器 `.post-wrap`、`.archive`、`.categories-card`、`.tag-cloud`。
- 内容统计标签 `.content-stats span`。
- 时间线、内容和标签面板 `.timeline-panel`、`.content-panel`、`.tag-cloud-panel`。
- 分类卡片 `.taxonomy-card` 与数量标签 `.taxonomy-count`。
- 标签云入口 `.tag-cloud-panel a`、`.tag-cloud-tags a`。
- 相册图片 `.ins-content img`。
- 友链引用面板 `.friends-panel blockquote`。

文章详情页：

- 文章标签 `.article-tags a`。
- 正文完整边框引用块和代码块外框。
- 版权信息 `.article-copyright`。
- 上一篇/下一篇导航卡片 `.article-nav a.prev`、`.article-nav a.next`。
- 文章目录 `.post-toc`。

### 3.4 保留或排除的边框

以下内容不统一改为微圆角：

- 仅有 `border-top`、`border-bottom` 或 `border-left` 的分隔线和强调线。
- 首页分区线、页头分隔线、页脚分隔线、文章头部分隔线和列表行分隔线。
- 正文链接的下划线式 `border-bottom`。
- 引用块用于强调的左侧粗边框；引用块外层完整边框仍可使用微圆角。
- 表格单元格内部网格线，避免每个单元格独立圆角导致边线断裂。
- `border: 0`、`border-collapse`、`border-spacing` 等非视觉边框声明。
- 圆形头像、圆点、图标等 `50%` 或 `100%` 圆角。
- 胶囊导航和线条等 `999px` 圆角。
- 已有 `9px`、`10px`、`11px`、`12px`、`13px`、`14px`、`16px` 圆角的组件，除非开发验证发现明显不一致并重新确认。

## 四、现状分析

### 4.1 项目结构

本项目是 Hexo 静态博客，当前主题为 `themes/chic/`：

- 页面模板位于 `themes/chic/layout/`。
- 主题样式位于 `themes/chic/source/css/`。
- `themes/chic/source/css/style.styl` 依次导入基础样式、页面样式、响应式样式，最后导入 `custom.styl`。
- 因为 `custom.styl` 最后加载，它是当前新版视觉覆盖的主要入口，适合承载本次统一规则。

### 4.2 边框与圆角现状

样式盘点结果：

- `custom.styl` 中存在约 106 行边框相关声明，是本次影响最大的文件。
- 基础文章、代码、导航和媒体样式文件中也存在少量边框规则，但多数可由最后加载的 `custom.styl` 安全覆盖。
- 当前已有圆角值包括 `2px`、`4px`、`9px`、`10px`、`11px`、`12px`、`13px`、`14px`、`16px`、`50%`、`100%`、`999px`。
- 分页器外层显式使用 `border-radius: 0`，但它只有顶部边框，属于分隔线容器，不应改为圆角面板。
- 大量新版内容卡片具有完整 `1px solid` 边框但没有圆角，是本次主要处理对象。

### 4.3 当前工作区状态

当前工作区存在未提交改动，包括：

- `AGENTS.md`
- `CLAUDE.md`
- `themes/chic/source/css/custom.styl`
- `docs/changes/` 下的变更记录

后续开发必须在现有工作区上做最小增量修改，保留顶部导航和文章上下篇导航等已有改动，不得覆盖或回退用户现有内容。

## 五、技术方案

### 5.1 设计规则

本次只调整形状，不调整颜色、字体、间距和布局：

- 颜色：继续沿用当前深色背景、绿色强调、蓝灰辅助色和浅色主题颜色。
- 字体：保持现有 HarmonyOS Sans SC 与主题字体设置。
- 布局：保持所有网格、卡片尺寸、响应式断点和排列方式。
- 形状：以 `4px` 微圆角作为直角完整边框的统一签名，视觉上只软化尖角，不把技术博客改造成大圆角卡片风格。

### 5.2 圆角变量

计划在 `custom.styl` 的设计变量区域增加：

```stylus
$radius-sm = 4px
```

本次新增规则统一引用该变量，避免重复硬编码。现有特殊圆角暂不迁移为变量，控制需求范围。

### 5.3 选择器级应用

采用显式组件选择器分组，不使用以下高风险方案：

- 不使用 `* { border-radius: ... }`。
- 不使用基于属性文本的宽泛选择器匹配所有带边框元素。
- 不通过 JavaScript 扫描元素或添加 class。

计划在相关组件现有规则内增加 `border-radius: $radius-sm`，或在 `custom.styl` 中建立按业务含义分组的选择器。优先靠近原组件声明，降低选择器权重冲突和后续维护成本。

### 5.4 内容裁切策略

仅在确有需要时增加 `overflow: hidden`：

- 已有装饰层可能越过边角的视觉容器保持或补充裁切。
- 普通内容面板不默认增加裁切，避免代码块阴影、焦点轮廓、定位元素或横向滚动被截断。
- 相册图片和代码块自身直接应用圆角，不依赖父级强制裁切。

### 5.5 深浅主题与响应式

`border-radius` 不依赖主题颜色，原则上无需分别编写深色和浅色覆盖。但开发时仍需验证：

- 浅色主题边框对比度下圆角是否清晰。
- 移动端卡片堆叠后边角是否正常。
- 首页技术视觉面板内部绝对定位元素是否被意外裁切。
- 文章代码块、表格横向滚动和目录固定定位是否正常。

### 5.6 替代方案

方案一：全局通配选择器统一圆角。

- 优点：代码少、覆盖面大。
- 缺点：会误伤分隔线、表格网格、圆形控件和特殊边框，风险不可控。
- 结论：不采用。

方案二：把所有已有圆角全部统一为 `4px`。

- 优点：数值高度统一。
- 缺点：会破坏胶囊导航、圆形图标和已完成的移动端控件设计，也超出“给没有圆角的边框增加小圆角”的必要范围。
- 结论：不采用。

方案三：按组件显式补充 `4px` 微圆角。

- 优点：范围可控，可保留特殊形状，便于测试和回滚。
- 缺点：需要完整盘点选择器，并对新增组件持续遵守变量规范。
- 结论：推荐采用。

## 六、影响范围

直接影响：

- 全站具有完整边框的卡片、面板、标签、图片、目录和文章导航。
- 深色和浅色主题下的边框形状。
- 桌面端与移动端的视觉细节。

不影响：

- Hexo 路由、文章数据、分类和标签数据。
- 页面模板结构和链接地址。
- 顶部导航、移动菜单、分页器和主题切换的交互逻辑。
- 文章 Markdown 内容。
- GitHub Pages 工作流和部署配置。

预计只修改主题样式与开发文档，属于视觉范围较广但逻辑风险较低的全站需求。

## 七、风险评估

### 7.1 主要风险

- `custom.styl` 最后加载且包含大量全局覆盖，选择器分组过宽可能影响非目标元素。
- 文章正文包含代码块、表格、图片、引用和历史 HTML，圆角与 `overflow` 组合可能造成内容裁切。
- 首页技术视觉面板包含伪元素和绝对定位节点，错误裁切可能破坏装饰布局。
- 一些组件已有特殊圆角，如果被统一覆盖为 `4px`，会破坏圆形或胶囊语义。
- 工作区已有未提交样式改动，开发时若整段替换可能覆盖既有修复。
- 只验证单个页面可能遗漏归档、标签、相册或浅色主题中的直角边框。

### 7.2 风险控制

- 只修改完整边框组件，明确排除单边分隔线和表格网格线。
- 使用 `$radius-sm` 变量和显式选择器，不使用全局通配。
- 不默认给普通面板添加 `overflow: hidden`。
- 开发前后对比 `custom.styl` 差异，确保已有修改被保留。
- 通过桌面端、移动端、深色、浅色四个维度抽样验证主要页面。

### 7.3 回滚方案

- 本次样式统一集中在 `$radius-sm` 和对应组件的 `border-radius` 声明。
- 如果整体效果不符合预期，可删除新增变量和本次新增的圆角声明，不需要回退模板或数据。
- 如果单个组件出现问题，可仅撤销该组件圆角，不影响其他页面。
