# 归档分类标签关于页面样式深度优化

## 一、需求背景

用户要求对以下页面进行样式深度优化：

- `http://localhost:4000/archives/`
- `http://localhost:4000/category/`
- `http://localhost:4000/tag/`
- `http://localhost:4000/about/`

用户表述为“三个页面”，但实际列出四个链接。为避免遗漏，本开发文档按四个页面处理，后续如用户确认只做其中三个页面，需要重新调整范围。

当前首页已经改为深色产品风格，但归档、分类、标签、关于页面仍主要沿用旧模板结构和基础样式，视觉层级、信息密度、卡片化组织、移动端阅读体验与首页不够统一。

## 二、需求目标

本次目标是让四个内容页与当前首页形成统一的视觉系统，并提升阅读和查找效率：

- 统一深色产品风视觉语言。
- 建立规范的页面头部、标题、说明文案、统计信息和列表样式。
- 优化归档页文章列表的年份分组、日期展示和 hover 状态。
- 优化分类页和标签页的入口卡片、数量展示和可点击区域。
- 优化关于页内容容器、正文层级、段落间距和移动端表现。
- 保持字号规范化，不新增随意字号。

## 三、需求范围

### 3.1 本次包含

- 优化 `/archives/` 归档页样式。
- 优化 `/category/` 分类页样式。
- 优化 `/tag/` 标签页样式。
- 优化 `/about/` 关于页样式。
- 必要时调整 EJS 模板结构，以支持更好的页面头部、统计信息和列表布局。
- 必要时修正这些页面模板中的可见乱码文案。
- 复用当前 `custom.styl` 中已有字号变量和色彩体系。
- 完成后运行 `npm run build` 验证。
- 完成后新增开发总结到 `docs/reviews/`。

### 3.2 本次不包含

- 不调整首页。
- 不修改文章正文内容。
- 不重构 Hexo 构建流程。
- 不新增第三方 UI 框架。
- 不处理所有历史 Markdown 文章的编码问题。
- 不处理当前工作区已有的其他无关改动。

## 四、现状分析

当前模板与样式情况：

- `themes/chic/layout/_page/archive.ejs`：按年份输出文章列表，结构简单，缺少页面头部说明、统计信息和更完整的信息层级。
- `themes/chic/layout/_page/category.ejs`：单分类页存在乱码标题，继续复用归档列表。
- `themes/chic/layout/_page/tag.ejs`：单标签页存在乱码标题，继续复用归档列表。
- `themes/chic/layout/_page/page.ejs`：关于页使用通用页面模板，内容容器可读性仍有优化空间。
- `themes/chic/source/css/custom.styl`：已有深色视觉、亮色模式、字号变量和基础归档/标签样式，可以继续扩展。
- `source/about/index.md`、`source/category/index.md`、`source/tag/index.md` 在当前终端读取时存在乱码显示，页面是否实际乱码需要以浏览器渲染和源文件编码为准。

## 五、技术方案

### 5.1 页面结构方案

- 为归档页增加统一页面头部区域，例如页面标题、说明文字、文章总数。
- 为分类页和标签页增加统一页面头部，并强化分类/标签集合的卡片样式。
- 对单分类页和单标签页的乱码标题进行中文化处理。
- 关于页保留 Markdown 内容渲染，但增强 `.page` 和 `.post-content` 的阅读布局。

### 5.2 样式方案

- 在 `custom.styl` 中新增一组内容页样式类，尽量避免影响首页。
- 统一使用已有字号变量：
  - `$text-sm` 用于辅助信息；
  - `$text-base` 用于正文；
  - `$text-lg` 用于列表标题；
  - `$text-xl`、`$text-section` 用于模块标题。
- 归档列表使用更清晰的行结构：年份、标题、日期、分隔线、hover 强调。
- 分类和标签使用卡片或标签云增强点击区域，保持深色与亮色模式一致。
- 移动端将多列布局降为单列，保证不横向溢出。

### 5.3 可选文案修正方案

如果页面可见标题存在乱码，本次可修正模板内固定文案，例如：

- 分类归档；
- 标签归档；
- 全部文章；
- 关于本站。

历史文章正文乱码不在本次处理范围内。

## 六、影响范围

可能影响的文件：

- `themes/chic/layout/_page/archive.ejs`
- `themes/chic/layout/_page/category.ejs`
- `themes/chic/layout/_page/tag.ejs`
- `themes/chic/layout/_page/page.ejs`
- `themes/chic/source/css/custom.styl`
- 必要时涉及 `source/about/index.md`、`source/category/index.md`、`source/tag/index.md`

影响页面：

- `/archives/`
- `/category/`
- `/tag/`
- `/about/`
- 单分类归档页；
- 单标签归档页。

不应影响首页结构和文章详情页主体逻辑。

## 七、风险评估

- 如果直接修改通用 `.post-wrap`、`.post-title`、`.post-content`，可能影响文章详情页，需要控制选择器范围。
- 分类、标签页面可能由多个模板组合生成，需要同时验证聚合页和单项归档页。
- 现有文件存在编码显示异常，若直接重写 Markdown 内容可能扩大范围，因此优先处理模板固定文案和样式。
- 移动端布局如果只按桌面设计，可能导致标签过密或列表信息溢出，需要重点测试。

## 八、测试重点

开发完成后需要验证：

- `npm run build` 通过。
- `/archives/` 页面年份分组、文章标题、日期展示正常。
- `/category/` 页面分类入口清晰，单分类页标题正常。
- `/tag/` 页面标签入口清晰，单标签页标题正常。
- `/about/` 页面正文标题、段落、列表在深色背景下可读。
- 深色与浅色模式下颜色、边框和 hover 状态正常。
- 移动端宽度下无横向滚动、文字不重叠。
