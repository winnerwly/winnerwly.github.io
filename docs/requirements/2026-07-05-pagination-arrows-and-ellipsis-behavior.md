# 分页箭头与省略号行为优化

## 一、需求背景

当前分页控件只展示数字页码，缺少上一页、下一页入口。用户希望分页组件符合常见后台管理系统、列表页和表格页的通用设计：数字页码为主体，两侧提供简洁箭头，页数较多时使用不可点击省略号折叠中间页码。

## 二、需求目标

实现一套完整、通用、可复用的分页选择组件展示方式，使归档、分类、标签等列表分页页面具备清晰的位置感、边界状态和翻页入口。

## 三、需求范围

### 3.1 本次包含

- 分页两侧增加上一页 `‹` 和下一页 `›`。
- 保留纯数字页码展示。
- 当前页使用明显选中状态。
- 总页数较少时直接展示全部页码。
- 总页数较多时保留首页、尾页和当前页附近连续页码。
- 使用不可点击省略号 `...` 表示折叠页码。
- 第一页禁用上一页，最后一页禁用下一页。
- 补充深色主题、浅色主题和移动端样式。

### 3.2 本次不包含

- 不新增跳转输入框。
- 不新增每页条数选择器。
- 不改变文章分页数量配置。
- 不调整归档、分类、标签页面主体结构。

## 四、现状分析

分页由 `themes/chic/layout/_partial/paginator.ejs` 统一输出，目前 `prev_next` 为 `false`，导致页面只输出数字页码和省略号。样式由 `themes/chic/source/css/custom.styl` 中的 `.pagination` 规则控制。

Hexo 的 `paginator` 可通过 `prev_next: true` 输出上一页和下一页入口，并配合 `end_size`、`mid_size` 控制首页、尾页和当前页附近页码。

## 五、技术方案

- 修改 `themes/chic/layout/_partial/paginator.ejs`：
  - 启用 `prev_next: true`；
  - 设置 `prev_text: '‹'`；
  - 设置 `next_text: '›'`；
  - 保持 `end_size: 1` 和 `mid_size: 2`。
- 修改 `themes/chic/source/css/custom.styl`：
  - 统一 `.page-number`、`.extend` 和 `.space` 的尺寸；
  - 为 `.extend` 箭头按钮提供相同按钮样式；
  - 为 `.space` 保持无边框、不可交互视觉；
  - 为 `.disabled` 提供不可用状态；
  - 保留当前页高亮状态；
  - 补充浅色主题和移动端规则。

## 六、影响范围

影响所有复用 `_partial/paginator.ejs` 的分页页面，包括：

- `/archives/`
- `/archives/page/2/`
- 分类分页页面；
- 标签分页页面。

不影响文章详情页上一篇/下一篇导航。

## 七、风险评估

- Hexo 生成的边界禁用结构可能是隐藏或 `disabled` 类，需要构建后检查实际 HTML。
- 箭头按钮加入后，小屏幕宽度更紧，需要移动端压缩按钮尺寸。
- 省略号不可点击，需要避免 hover 样式误导用户。

## 八、测试重点

- 验证第一页展示：`‹ 1 2 3 ... 5 ›`，上一页不可用。
- 验证中间页展示：`‹ 1 ... 2 3 4 5 ›` 或相近结构。
- 验证最后一页展示：下一页不可用。
- 验证省略号不可点击且视觉弱化。
- 验证 `/archives/`、`/archives/page/2/`、分类分页和标签分页可访问。
- 执行 `npm run build`，确认构建无错误。
