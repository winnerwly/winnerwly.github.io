# 首页内容概要重梳理开发文档

## 需求背景

当前首页需要承担“全站内容概要”的角色，但现状信息组织较散：首屏、内容分区、最近文章和站点入口之间缺少清晰层级，页面读起来更像若干资源块的拼接，不能快速说明这个博客主要写什么、有哪些内容方向、读者下一步应该去哪里。

用户明确反馈：“首页是整体内容的概要，当前太乱了，重新梳理下。”

## 需求目标

1. 将首页重新定位为博客整体内容的导航和摘要，而不是单纯展示几个入口。
2. 首屏明确表达站点主题：前端工程、AI 编程、开发实践、问题复盘与个人沉淀。
3. 用更清晰的信息结构串联：站点介绍、内容方向、最新文章、分类/标签入口、关于页面等。
4. 修复首页模板中已经出现的中文乱码文案。
5. 保持现有 Hexo + Chic 主题技术栈，不引入新依赖。
6. 保持深色/浅色主题和移动端适配可用。

## 需求范围

本次计划只调整首页相关内容结构和样式：

- 首页模板：`themes/chic/layout/index.ejs`
- 首页实际内容局部：`themes/chic/layout/_page/profile.ejs`
- 首页样式：`themes/chic/source/css/custom.styl`
- 如有必要，微调主题配置读取方式：`themes/chic/_config.yml`

不在本次范围内：

- 不改文章正文内容。
- 不改文章 URL、分类 URL、标签 URL。
- 不重构整个主题模板系统。
- 不调整 GitHub Pages 部署流程。
- 不提交 `public/` 生成产物。

## 当前状态分析

1. `themes/chic/layout/index.ejs` 仅在首页渲染 `_page/profile`，所以首页主要改动应集中在 `profile.ejs` 与相关样式。
2. `themes/chic/layout/_page/profile.ejs` 当前包含 hero、资源区、最近文章列表、模板系统入口等内容，但中文文案已出现乱码，需要整体替换。
3. `themes/chic/source/css/custom.styl` 中首页类名主要是 `home-template`、`download-hero`、`resource-section`、`resource-grid`、`download-list` 等，命名和内容语义偏“下载/资源”，与博客概要页不完全匹配。
4. 现有文章内容已经覆盖 AI、前端、工程实践、开发者成长等方向，首页可以从这些真实内容出发组织摘要。
5. 主题当前已有深色/浅色切换、桌面/移动导航和响应式样式，本次应沿用现有机制，避免扩大影响。
6. 工作区已有未提交改动，开发时需要在现有改动基础上谨慎编辑，不回退用户已有内容。

## 首页信息架构方案

计划将首页整理为以下模块：

1. 首屏总览
   - 标题：突出“前端工程师的小站”或“前端小站”。
   - 副标题：说明这里沉淀前端工程、AI 编程、问题排查、开发效率和个人实践。
   - 主操作：进入文章归档。
   - 次操作：查看分类/关于。

2. 内容方向概览
   - 使用 3 到 4 个方向块概括站点内容。
   - 建议方向：
     - AI 与开发者成长
     - 前端工程实践
     - JavaScript / CSS / 浏览器基础
     - 工具、效率与问题复盘
   - 每个方向给一句简短说明，并链接到归档、分类或标签页。

3. 最新文章
   - 保留动态读取 `site.posts.sort('date', -1).limit(...)`。
   - 展示日期、标题、标签或分类摘要。
   - 数量建议 5 到 6 篇，避免首页过长。

4. 全站入口
   - 用更克制的方式提供 `archives`、`category`、`tag`、`about`、`friends`、`ins` 等入口。
   - 入口说明短而明确，避免文案堆叠。

5. 站点概况
   - 展示文章总数、主要分类/标签入口。
   - 如 Hexo 数据读取稳定，可显示分类数量或标签数量；若模板环境不稳定，则只保留文章总数，降低风险。

## 技术方案

1. 重写 `profile.ejs`
   - 移除乱码文案。
   - 将页面结构改成语义清晰的 `home-hero`、`home-section`、`topic-grid`、`latest-list`、`site-links` 等。
   - 使用 Hexo 的 `url_for`、`site.posts`、`post.path`、`post.title`、`post.date`、`post.tags` 等现有能力。

2. 调整 `custom.styl`
   - 用新首页类名替代或兼容旧类名。
   - 保留整体深色科技感，但减少模块堆叠感。
   - 强化层级：首屏简介、内容方向、最近文章、站点入口。
   - 检查移动端布局，确保文字不重叠、不溢出。

3. 控制影响范围
   - 不改动文章页、归档页、分类页、标签页的现有结构。
   - 对全局样式只做首页必要调整。

## 受影响文件

- `themes/chic/layout/_page/profile.ejs`
- `themes/chic/source/css/custom.styl`
- 可能检查但尽量不修改：`themes/chic/layout/index.ejs`

## 验证计划

1. 运行 `npm run build`，确认 Hexo 可以正常清理并生成静态站点。
2. 如需视觉检查，运行 `npm run start` 后查看首页。
3. 检查首页桌面端：
   - 首屏主题明确。
   - 内容方向清楚。
   - 最新文章可点击。
   - 站点入口可点击。
4. 检查移动端：
   - 导航不遮挡内容。
   - 卡片或列表不横向溢出。
   - 长标题可换行或省略，不破坏布局。
5. 检查深色/浅色主题：
   - 文字对比度足够。
   - 边框、按钮、列表 hover 状态可读。

## 风险与取舍

1. 当前首页相关文件已有乱码，直接局部修补可能遗漏问题，因此建议整体替换首页文案和结构。
2. 若读取标签/分类数量在 Hexo 模板中存在兼容风险，优先使用文章总数和固定入口，保证构建稳定。
3. 首页若加入过多模块会重新变乱，因此本次以“概要 + 导航”为主，不做复杂数据看板。
4. 现有样式使用深色背景和绿色强调色，本次沿用该视觉方向，避免与导航、文章页割裂。
