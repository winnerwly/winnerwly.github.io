# 相册与友链页面样式优化

## 一、需求背景

用户要求继续优化以下两个页面：

- `http://localhost:4000/ins/`
- `http://localhost:4000/friends/`

当前这两个页面仍保留旧模板风格，与新首页以及即将优化的归档、分类、标签、关于页面不够统一。其中 `/ins/` 页面存在模板内联样式和乱码标题，`/friends/` 页面内容较少，缺少页面说明、视觉层级和友链展示结构。

## 二、需求目标

本次目标是将相册页和友链页纳入统一的深色产品风页面体系：

- 修正页面可见乱码标题。
- 去除或迁移 `ins.ejs` 中的内联样式。
- 优化相册图片展示，让图片网格、间距、边框、暗色背景更协调。
- 优化友链页内容结构，使其具备清晰的页面头部、说明文案和联系入口。
- 保持深色和浅色模式一致。
- 保持字号规范化，不新增随意字号。

## 三、需求范围

### 3.1 本次包含

- 优化 `/ins/` 相册页模板和样式。
- 优化 `/friends/` 友链页模板和样式。
- 必要时修正 `source/ins/index.md`、`source/friends/index.md` 中的可见乱码文案。
- 将页面相关样式统一放入 `themes/chic/source/css/custom.styl`。
- 完成后运行 `npm run build` 验证。
- 完成后新增开发总结到 `docs/reviews/`。

### 3.2 本次不包含

- 不新增真实友链数据。
- 不新增相册图片资源。
- 不引入图片灯箱、瀑布流库或第三方 UI 框架。
- 不处理所有历史 Markdown 文章编码问题。
- 不处理当前工作区已有的其他无关改动。

## 四、现状分析

当前相关文件如下：

- `themes/chic/layout/ins.ejs`：页面标题存在乱码，模板内包含 `<style>` 内联样式，不利于统一维护。
- `themes/chic/layout/friends.ejs`：结构较简单，页面标题来自 Markdown Front Matter，但源文件读取时显示乱码。
- `source/ins/index.md`：标题和图片 alt 文案读取时显示乱码，内容只有两张图片。
- `source/friends/index.md`：标题和说明文案读取时显示乱码，内容只有一段引用提示。
- `themes/chic/source/css/custom.styl`：已有全局暗色/亮色样式和字号变量，可继续扩展。

## 五、技术方案

### 5.1 相册页方案

- 将 `ins.ejs` 改为统一页面结构，使用中文标题“照片墙”或“相册”。
- 移除模板内联 `<style>`，将 `.ins-content`、图片网格、图片边框、hover 状态写入 `custom.styl`。
- 将 Markdown 里的图片按响应式网格展示，桌面端多列，移动端单列或双列。
- 图片保持原图比例，避免拉伸变形。

### 5.2 友链页方案

- 将 `friends.ejs` 改为统一页面结构，使用中文标题“友链”。
- 增加页面说明区域，例如“欢迎交换链接，可通过邮箱联系”。
- 当前没有结构化友链数据，因此先优化已有 Markdown 内容的展示，不新增虚假链接。
- 如需要后续扩展，可预留 `.friends-content` 和 `.friend-card` 样式。

### 5.3 样式方案

- 复用 `$text-sm`、`$text-base`、`$text-lg`、`$text-section` 等已有字号变量。
- 样式集中写入 `custom.styl`，避免模板内联样式。
- 深色模式使用当前绿色强调色；浅色模式补充对应背景、边框和文字颜色。

## 六、影响范围

可能影响的文件：

- `themes/chic/layout/ins.ejs`
- `themes/chic/layout/friends.ejs`
- `themes/chic/source/css/custom.styl`
- 必要时涉及 `source/ins/index.md`
- 必要时涉及 `source/friends/index.md`

影响页面：

- `/ins/`
- `/friends/`

不影响首页、归档、分类、标签、关于页，除非后续与上一份页面优化需求合并实施。

## 七、风险评估

- `source/ins/index.md` 和 `source/friends/index.md` 存在编码显示异常，直接改写需要谨慎，避免破坏内容。
- 相册图片数量较少，如果使用过重网格样式，页面可能显得空，因此布局应适合少量图片。
- 友链页缺少真实数据，不应为了视觉效果添加虚假内容。
- 若与其他页面优化同时开发，需要注意样式选择器不要互相覆盖。

## 八、测试重点

开发完成后需要验证：

- `npm run build` 通过。
- `/ins/` 标题正常，图片展示不变形，移动端不溢出。
- `/friends/` 标题和说明文案正常，内容层级清晰。
- 深色与浅色模式下文字、边框、背景、hover 状态正常。
- 页面样式与首页及其他内容页保持统一。
