# 移动端菜单栏样式优化开发文档

## 需求名称

移动端菜单栏样式优化

## 一、需求背景

当前移动端菜单栏已经具备基础可用性：顶部显示站点名称、主题切换按钮和“菜单”按钮，点击后全屏展开菜单列表。但从视觉体验看，当前样式仍偏基础：

- 顶部菜单按钮是文字按钮，视觉识别度弱。
- 菜单展开后像普通列表，缺少面板层级和入口分组感。
- 菜单关闭按钮在列表底部，操作路径不够自然。
- 菜单项之间只有分隔线，和站点整体的技术感、卡片层次不够统一。
- 移动端导航是全站公共区域，会影响首页、归档页、文章页等所有页面，需要谨慎处理。

## 二、需求目标

本次目标是优化移动端菜单栏的审美与可用性：

- 顶部导航更像稳定的移动端 app bar，空间更紧凑、按钮更清晰。
- 菜单按钮从纯文字改为更有识别度的图标/短文案组合或图标化样式。
- 展开菜单改为更有层级的全屏抽屉面板。
- 菜单项做成更精致的入口行，保留图标，同时增强 hover/active 视觉。
- 关闭入口上移到菜单面板顶部，减少用户寻找成本。
- 保持深色/浅色主题兼容。
- 保持移动端无横向溢出。

本次不包含：

- 不修改桌面端导航结构。
- 不调整站点路由、链接目标和菜单项数量。
- 不引入新依赖。
- 不改动文章、归档、分类、标签页面主体布局。

## 三、需求范围

计划涉及文件：

- `themes/chic/layout/_partial/header.ejs`
- `themes/chic/source/css/custom.styl`

可能检查但尽量不改：

- `themes/chic/source/js/script.js`

页面范围：

- 所有移动端页面的公共导航区域。

适配范围：

- 390px 左右手机宽度。
- 平板窄屏，`max-width: 1023px` 区间。
- 深色主题与浅色主题。

## 四、现状分析

移动端导航模板位于 `themes/chic/layout/_partial/header.ejs`，样式主要在 `themes/chic/source/css/custom.styl` 的 `@media (max-width: 1023px)` 中。

当前结构：

- `.navbar-mobile`
- `.navbar-header`
- `.mobile-actions`
- `.theme-toggle-mobile`
- `.menu-toggle`
- `#mobile-menu`
- `.menu-item`
- `.menu-close`

当前样式特点：

- 移动端菜单通过 `transform: translateX(100%)` 隐藏，展开后全屏覆盖。
- 菜单项使用图标 + 文案，纵向排列。
- 顶部按钮和关闭按钮都是文字按钮。

主要问题：

- 顶部按钮形态不够精致，和页面整体视觉不统一。
- 菜单面板缺少标题区、关闭区和内容区分层。
- 菜单项的视觉反馈较弱。
- 关闭按钮位置靠后，不符合常见移动端菜单习惯。

## 五、技术方案

### 1. 顶部导航优化

- 调整 `.navbar-mobile .navbar-header` 的高度、背景、边框和内边距。
- 优化站点 Logo 的字号、字重和移动端间距。
- 将 `.mobile-actions` 做成更整齐的按钮组。
- 优化 `.menu-toggle` 视觉，减少纯文字按钮的粗糙感。

### 2. 菜单面板优化

- 为 `#mobile-menu` 增加菜单头部区域，包含站点名称和关闭按钮。
- 将关闭按钮从底部移动到面板顶部。
- 使用更柔和的背景层次、边框和面板内边距。
- 保持 `transform` 展开方式，避免横向溢出。

### 3. 菜单项优化

- 菜单项调整为卡片式或列表卡片式入口。
- 图标区域固定尺寸，文字居中对齐。
- 增加 hover/active 状态。
- 深色主题下保持绿色强调，浅色主题下使用更轻的边框与背景。

### 4. 响应式与可访问性

- 保持按钮为原生 `button`，链接为 `a`。
- 保留现有 `aria-label`。
- 确保 390px 宽度不出现横向滚动。
- 菜单展开和关闭逻辑沿用现有 `mobileBtn()`，不新增复杂脚本。

## 六、影响范围

直接影响：

- 所有页面的移动端顶部导航。
- 移动端菜单展开面板。

不影响：

- 桌面端导航。
- 页面正文内容。
- 文章、分类、标签、归档 URL。
- Hexo 构建配置。

## 七、风险评估

- 移动端导航是公共区域，样式选择器需要限定在 `.navbar-mobile` 内，避免影响桌面端 `.navbar`。
- 菜单结构如果调整不当，可能影响现有 `mobileBtn()` 的 class 切换，需要保持 `#mobile-menu` 和 `.menu-toggle` 不变。
- 关闭按钮位置调整涉及模板结构，需要验证点击关闭仍然可用。
- 深色/浅色主题都需要同步覆盖，否则主题切换后可能出现对比度不足。

## 八、测试重点

- `npm run build` 构建通过。
- 390px 移动端顶部导航无横向溢出。
- 菜单按钮可打开菜单。
- 菜单内关闭按钮可关闭菜单。
- 菜单项链接仍可点击。
- 深色主题和浅色主题下菜单面板均可读。
- 桌面端导航不受影响。
