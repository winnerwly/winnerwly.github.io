# 首页设计审美丰富化开发文档

## 需求名称

首页设计审美丰富化

## 一、需求背景

当前首页已经完成内容概要重梳理，能够表达站点主题、内容方向、最新文章和常用入口，信息结构基本清晰。但从实际页面观察来看，首页视觉仍偏“工程化平铺”：首屏以大标题、按钮和统计块为主，整体层次较硬，缺少更有记忆点的视觉资产与页面节奏；卡片、列表和分区边界多依赖直线与半透明底色，审美丰富度还有提升空间。

用户提出“丰富首页的设计审美”，期望首页在保持前端技术博客气质的基础上，更具设计感、辨识度和浏览吸引力，而不是只完成信息陈列。

补充观察：

- 桌面端首屏已有深色背景、绿色强调色、导航图标和内容卡片，但视觉重心主要集中在文字块，缺少辅助构图。
- 内容方向卡片边界清晰但较平，卡片之间的层次差异不明显。
- 最新文章区域偏列表化，阅读节奏略单一。
- 移动端首屏存在横向溢出迹象，顶部菜单与按钮区域略显拥挤，需要在视觉升级时同步关注。

## 二、需求目标

本次目标是在不推翻现有首页信息架构的前提下，提升首页的视觉表现力和完成度：

- 强化首屏第一印象，让首页更像一个有设计主张的个人技术站入口。
- 增加更丰富的背景层次、构图元素、卡片状态和分区节奏。
- 保持站点当前“深色、技术感、绿色强调”的识别方向，同时避免单调的纯黑平铺。
- 优化桌面端与移动端的视觉稳定性，避免横向溢出、文字遮挡、按钮拥挤。
- 继续支持深色/浅色主题切换，确保两套主题下文字对比度和边界层次可读。

本次不包含：

- 不重新改写首页内容定位。
- 不调整文章正文、分类、标签、归档等页面的信息架构。
- 不引入新的前端框架或构建依赖。
- 不提交 `public/` 等生成产物。

## 三、需求范围

计划涉及的主要文件：

- `themes/chic/layout/_page/profile.ejs`
- `themes/chic/source/css/custom.styl`
- 必要时检查但尽量不改：`themes/chic/layout/index.ejs`
- 必要时检查但尽量不改：`themes/chic/source/css/_partial/header.styl`
- 必要时检查但尽量不改：`themes/chic/source/js/script.js`

页面范围：

- 首页：`/`

适配范围：

- 桌面端首屏与完整首页。
- 移动端首屏、内容卡片、最新文章、快捷入口。
- 深色主题与浅色主题。

## 四、现状分析

首页当前由 `themes/chic/layout/index.ejs` 在首页场景下加载 `_page/profile.ejs`，首页样式主要集中在 `themes/chic/source/css/custom.styl`。

当前视觉特点：

- 主色为接近黑色的深色背景，强调色为高饱和绿色。
- 首页包含首屏介绍、行动按钮、站点统计、内容方向卡片、最新文章列表、站点入口。
- 内容结构已经比传统博客首页更清晰，适合继续在现有结构上增强视觉，而不需要重做信息架构。

当前主要不足：

- 首屏缺少能体现“前端工程、AI 编程、实践沉淀”的视觉构图。
- 首页大面积区域使用相似的边框、背景透明度和直角卡片，模块之间差异感不足。
- 统计块、主题卡片、快捷入口的视觉语言接近，用户浏览时层次感不够鲜明。
- 移动端检测到 `documentElement.scrollWidth > clientWidth`，说明存在横向溢出风险，需要在本次样式调整中修复。

## 五、技术方案

### 1. 首屏视觉增强

在 `home-hero` 内增加一个右侧或背景型视觉面板，用纯 CSS 构建技术感图形，例如：

- 多层细线网格。
- 代码片段式标签。
- 小型终端/流程节点视觉块。
- 轻量扫描线或坐标轴效果。

该视觉元素只作为装饰与氛围，不承载核心信息，避免影响可访问性和移动端阅读。

### 2. 背景与空间层次优化

在 `body:after` 或首页容器内调整背景层次：

- 增加更细腻的径向光、线性渐变和网格纹理。
- 控制绿色强调色面积，避免页面变成单一绿色主题。
- 保持深色主题沉稳，浅色主题则使用更轻的玻璃感和淡色背景层次。

### 3. 卡片系统升级

针对 `topic-card`、`home-stats`、`site-link-card` 做差异化处理：

- 内容方向卡片增加悬浮位移、强调边线、顶部编号或角标。
- 统计块从普通卡片升级为更有节奏的指标条，减少平铺感。
- 快捷入口更轻量，避免与内容方向卡片争夺视觉重心。

### 4. 最新文章区域优化

保持现有动态文章读取逻辑，优化展示方式：

- 日期、标题、标签之间建立更清晰的扫描路径。
- hover 状态增加左侧强调线或背景高亮。
- 移动端允许标题自然换行，避免横向滚动。

### 5. 响应式与溢出修复

重点检查并修复移动端横向溢出：

- 控制大标题、按钮、统计块、网格视觉元素的最大宽度。
- 对装饰元素设置 `overflow: hidden` 或在移动端隐藏/降级。
- 优化移动端导航按钮尺寸与间距，避免顶部区域拥挤。
- 保证 `html`、`body`、首页容器不出现非预期横向滚动。

### 6. 主题兼容

深色主题延续当前视觉方向，浅色主题提供对应颜色变量或局部覆盖：

- 深色：黑色基底、绿色强调、低饱和蓝灰辅助色。
- 浅色：浅灰白基底、绿色强调、深灰正文、柔和边框。

不新增运行时逻辑，优先通过 CSS 和已有主题 class 完成。

## 六、影响范围

直接影响：

- 首页首屏视觉。
- 首页内容方向卡片。
- 首页最新文章列表。
- 首页快捷入口。
- 首页移动端布局。

可能间接受影响：

- `custom.styl` 中存在部分全局样式，修改时需要避免波及文章页、归档页、分类页、标签页和关于页。
- 深色/浅色主题切换样式可能需要同步调整，避免某些卡片在浅色主题下对比度不足。

不影响：

- 文章 URL。
- Hexo 数据结构。
- 文章 Markdown 内容。
- GitHub Pages 工作流。
- 站点部署配置。

## 七、风险评估

- 视觉元素过多可能影响首页加载与可读性，需要保持 CSS 级轻量实现。
- 装饰性背景如果层级不当，可能遮挡正文或降低对比度，需要重点检查。
- 移动端空间有限，桌面端的视觉面板需要在窄屏下重排、缩小或隐藏。
- 由于 `custom.styl` 承载了较多页面样式，选择器需要尽量限定在首页相关 class 下，避免误伤内页。
- 当前项目有中文文档与模板内容，编辑时需要保持 UTF-8，避免再次出现中文乱码。

回滚方案：

- 本次计划集中改动首页模板和首页样式，如效果不符合预期，可回退对应文件的本次改动。
- 若仅部分视觉元素存在问题，可优先移除装饰面板与新增背景层，保留基础布局优化。

## 八、测试重点

开发完成后需要验证：

- `npm run build` 可以正常清理并生成静态文件。
- 首页桌面端首屏视觉完整，文字、按钮、视觉面板不重叠。
- 首页移动端无横向滚动，重点检查 390px 左右宽度。
- 首页最新文章标题、标签、日期在桌面端和移动端均可读。
- 深色主题下背景层次、卡片边框、hover 状态清晰。
- 浅色主题下文字对比度足够，卡片和背景不显脏。
- 导航菜单、主题切换按钮、首页链接仍可正常点击。
