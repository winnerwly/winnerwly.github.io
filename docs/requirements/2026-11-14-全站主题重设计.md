# 全站主题重设计

## 一、需求背景

站点使用 Hexo 的 Chic 主题。现有首页采用终端装饰、专题卡片和快捷入口，内页则大多沿用顶部标题区加内容面板的布局。用户希望重写整站主题。首轮预览采用固定侧栏、大字号刊物标题和单独的头条区，用户反馈「AI 味道太重」，随后指定以 Chic 官方演示为本次设计参考。

## 二、需求目标

- 将站点做成以作者和文章为主的个人技术博客。
- 首页首屏呈现作者身份与入口。浏览文章通过顶部导航与作者区进入归档。文章详情用稳定的正文宽度和清晰的标题层级承载长文。
- 沿用 Chic 的浅色白底与深色炭灰底，正文与导航以中性色为主。链接通过下划线、悬停与焦点体现可交互状态。全站使用系统中文字体。

## 三、需求范围

| 页面 | 拟采用的布局 |
| --- | --- |
| 全站框架 | 桌面页头左侧为站名，右侧为文字导航和主题切换。窄屏显示站名、主题切换及可展开的菜单。页脚居中，主内容宽度与页头分别约束。 |
| 首页 | 第一页改为垂直居中的作者页。按圆形头像、Mr.w、现有个人简介、文章与 GitHub 入口的顺序展示。文章入口指向归档。已有首页分页路径继续展示对应的文章列表。 |
| 文章归档 | 年份作为组标题，组内以标题靠左、日期靠右排列，窄屏允许日期另起一行。列表底部提供分页。 |
| 分类和标签 | 分类索引使用单栏文字列表，显示名称、数量及近期文章。标签索引用紧凑的文字链接呈现名称与数量。分类和标签详情复用文章行。 |
| 文章详情 | 以标题、作者、日期、分类和正文组成阅读区。正文宽度约 720 像素，宽屏在正文侧边展示轻量目录，窄屏在正文前提供可展开的目录。保留标签、可配置的版权信息和上下篇链接。 |
| 关于、友链与通用页面 | 采用窄栏阅读排版。继续渲染原有 Markdown 内容及链接。 |
| INS 照片墙 | 使用现有照片组成响应式网格，保持图片比例及原有内容顺序。 |

本次范围为主题的模板、样式和相关前端交互。新增功能如全文搜索、评论和第三方服务，以及文章内容、站点路由、构建依赖和 GitHub Pages 部署配置均在本次范围之外。

## 四、现状分析

- `themes/chic/layout/layout.ejs` 组织所有页面的公共框架。头部模板分别输出宽屏导航和窄屏弹层，文章目录由 Tocbot 生成。
- `themes/chic/source/css/style.styl` 引入基础样式、页面样式、响应式样式和约两千行的 `custom.styl`。部分公共规则分散在不同文件，继续叠加覆盖会增加移动端与主题切换的验证成本。
- `index.ejs` 通过 `is_home()` 使用首页模板，首页的最近文章直接取全站最新六篇。Hexo 已生成 `/page/2/` 等分页路由，首页列表可使用当前页的 `page.posts` 和分页数据。
- 分类索引已按分类最近一次发文时间排序。文章正文包含代码块、表格、图片和旧文章兼容内容，需要用实际页面验证。

## 五、技术方案

### 设计参考

| 主题 | 应用于本站的做法 |
| --- | --- |
| [Chic 官方首页](https://siricee.github.io/hexo-theme-Chic/) | 参照顶部导航、留白、居中作者区及底部署名。使用本站头像、昵称、个人简介和链接。 |
| [Chic 官方归档](https://siricee.github.io/hexo-theme-Chic/archives/) | 参照年份分组、左侧标题与右侧日期的文章行。 |
| [Chic 正文示例](https://siricee.github.io/hexo-theme-Chic/2019/06/11/markdown_test/) | 参照窄栏正文和标题下的元信息，用本站的长文检查标题、引用、表格和代码块。 |

### 实现步骤


1. 保留 `themes/chic/` 作为当前 Hexo 主题入口，重写 EJS 公共框架及页面模板。共用文章列表行、分页与基础容器，使用 Hexo 提供的文章、归档及分类标签数据生成 HTML。
2. 新建统一的 Stylus 颜色、间距、字号与容器变量，按公共框架、列表、正文和独立页面组织样式。逐项核对依赖关系后，移除被整体替代的旧主题样式。继续使用现有本地字体与内容图片。
3. 导航复用同一组站内入口，按当前路由展示选中状态。窄屏菜单支持键盘打开、关闭与焦点返回，主题切换沿用 `theme-preference` 存储键和站点现有的默认深色行为。
4. 文章目录沿用现有标题锚点及 Tocbot，重排显示位置并支持窄屏展开。正文保留 Hexo 生成的语法高亮标记和公式加载条件，长代码和表格在内容区内横向滚动。
5. 沿用现有 URL、分类排序及 Markdown 数据。采用原主题内替换方案，可在同一构建环境下直接核对改版前后的输出路径。

## 六、影响范围

- 影响 `themes/chic/layout/`、`themes/chic/source/css/` 与必要的 `themes/chic/source/js/`。
- 所有使用 Chic 主题渲染的页面和分页路由都会应用新样式。原站点链接、文章资源位置、前置元数据和生成规则继续沿用。
- 项目为静态站点，改版不涉及接口、权限、存储结构或数据迁移。

## 七、风险评估

| 风险 | 处理方式 |
| --- | --- |
| 长标题、表格与代码撑开窄屏网格 | 使用允许收缩的内容列、标题换行和局部滚动。 |
| 文章目录切换版式后，锚点跳转或当前标题状态发生回归 | 检查有目录、无目录及多级标题文章，并测试点击与滚动定位。 |
| 两套配色中的链接、代码高亮或焦点难以辨识 | 复用同一组语义颜色变量，检查深浅主题及键盘焦点。 |
| 重写模板时遗漏历史路由或资源引用 | 构建前后比对生成路由，抽查典型文章资源、归档分页和分类及标签链接。 |

上线后的回滚方式为回退此次主题改动并重新生成站点。原文章与配置无需迁移。

## 八、测试重点

- 执行 `npm run build`，验证 Hexo 生成成功并比对改版前后的页面路径。
- 通过本地预览验证首页和首页第二页、归档及其分页、分类和标签的索引和详情、文章详情、关于、友链和 INS。
- 在 360、768、1280 像素宽度分别检查主要页面。验证窄屏菜单、主题切换及刷新记忆、键盘焦点、目录、上下篇、长标题、代码、表格和图片。
- 保存有代表性的桌面端和移动端截图，支持界面改动验收。完成后在 `docs/reviews/` 记录与需求方案的对照及验证结果。
