# 顶部导航栏重写与移动端兼容开发文档

## 需求名称

顶部导航栏重写与移动端兼容

## 一、需求背景

当前站点顶部导航栏已经经过多轮样式调整，但整体仍存在“局部补丁叠加”的问题：

- 桌面端和移动端分别使用 `.navbar` 与 `.navbar-mobile` 两套结构，链接内容重复，后续维护容易出现两端不一致。
- 移动端菜单虽然已修复基础可用性，但仍依赖原主题旧样式覆盖，选择器权重较复杂，容易在后续改动中再次错位。
- 顶部导航是全站公共区域，当前设计与首页、归档页等新视觉方向还不够统一。
- 移动端需要兼顾紧凑、可触达、无横向溢出、菜单开关明确、主题切换可用等基础体验。

本次希望对顶部导航栏进行一次更系统的重写，不只是继续修补单个按钮或单个菜单样式。

## 二、需求目标

本次目标：

- 重写顶部导航栏结构，使桌面端和移动端共享更一致的语义与视觉体系。
- 保留现有导航入口：首页、文章、INS、分类、标签、关于、友链。
- 保留主题切换功能，并确保桌面端与移动端都可使用。
- 桌面端导航呈现为更精致、稳定、与站点整体视觉统一的顶部栏。
- 移动端导航呈现为紧凑 app bar，并提供可读、易关闭、无横向溢出的菜单面板。
- 优化菜单打开/关闭状态，包括按钮状态、可访问属性和必要的页面滚动控制。
- 保持 Hexo 静态站点构建方式，不引入新依赖。

本次不包含：

- 不新增或删除导航链接。
- 不调整文章、归档、分类、标签等页面主体布局。
- 不调整站点路由、Hexo 配置、分页配置。
- 不引入前端框架或新的构建工具。
- 不处理登录、搜索、评论等非导航需求。

## 三、需求范围

计划涉及文件：

- `themes/chic/layout/_partial/header.ejs`
- `themes/chic/source/css/custom.styl`
- `themes/chic/source/js/script.js` 或现有内联脚本区域

页面范围：

- 全站所有页面的顶部公共导航区域。

适配范围：

- 桌面端宽度：`1024px` 及以上。
- 移动端与窄屏宽度：`1023px` 及以下。
- 常见手机宽度：`360px`、`390px`、`414px`。
- 深色主题与浅色主题。

## 四、现状分析

当前模板位于 `themes/chic/layout/_partial/header.ejs`，主要结构为：

- 桌面端：`nav.navbar`
- 移动端：`nav.navbar-mobile`
- 菜单项在桌面端和移动端重复书写。
- 移动端通过 `mobileBtn()` 切换 `.menu-toggle` 与 `#mobile-menu` 的 `active` class。

当前样式主要位于 `themes/chic/source/css/custom.styl`：

- `.navbar` 负责桌面端 sticky 顶栏。
- `.navbar-mobile` 默认隐藏，在 `@media (max-width: 1023px)` 下显示。
- 移动端菜单使用 `position: fixed` 与 `transform: translateX(100%)` 做抽屉动画。
- 为避免主题原始样式干扰，当前已有 `.navbar-mobile .container .menu` 的高权重覆盖。

主要问题：

- 两套导航结构重复，维护成本高。
- 移动端样式存在对旧主题规则的覆盖依赖，长远看不够干净。
- 当前 `mobileBtn()` 只切换 class，没有同步 `aria-expanded`、`aria-hidden`，也没有处理菜单打开后的页面滚动。
- 导航栏整体视觉还可以更统一，例如桌面端导航项状态、移动端菜单头部、按钮层级与站点品牌呈现。
- 当前模板中中文内容在部分终端读取时出现乱码显示，需要开发时谨慎保留文件实际编码，避免误改中文文案。

## 五、技术方案

### 1. 模板结构重写

- 将导航栏重写为一个更清晰的 `site-header` 结构，尽量减少桌面端和移动端重复代码。
- 保留品牌区、导航链接区、操作按钮区三个核心区域。
- 导航链接使用同一组 `.nav-link` 样式类，在桌面端横向展示，在移动端进入菜单面板。
- 移动端菜单按钮使用独立按钮，并保留清晰的 `aria-label`、`aria-expanded`、`aria-controls`。
- 移动端菜单面板增加面板头部和关闭按钮，便于用户快速关闭。

### 2. 桌面端视觉方案

- 顶部导航保持 sticky。
- 使用半透明背景、模糊、细边框和轻微阴影，形成更稳定的顶部层级。
- 品牌区保持“前端小站”的技术感强调色。
- 导航链接使用胶囊或轻量标签式 hover 状态，避免文字漂浮。
- 主题切换按钮与导航按钮保持统一尺寸、边框和交互反馈。

### 3. 移动端视觉方案

- 移动端顶部栏控制在约 `60px` 至 `64px` 高度。
- 左侧显示品牌，右侧显示主题切换和菜单按钮。
- 菜单面板使用固定定位覆盖视口，避免受父容器布局影响。
- 菜单项采用大点击区域，保证触控可用性。
- 菜单打开后避免横向溢出，必要时对 `html`、`body` 做滚动控制。
- 对 `360px`、`390px`、`414px` 宽度进行验证。

### 4. 交互与可访问性

- 打开菜单时：
  - 菜单按钮设置 `aria-expanded="true"`。
  - 菜单面板设置可见状态。
  - 页面主体滚动可临时锁定，避免背景滚动干扰。
- 关闭菜单时：
  - 恢复 `aria-expanded="false"`。
  - 移除菜单激活状态。
  - 恢复页面滚动。
- 保留点击关闭按钮关闭菜单。
- 如实现成本可控，可增加 `Esc` 关闭菜单，但不作为强制目标。

### 5. 兼容与回滚方案

- 优先只改主题模板和主题样式，不触碰 Hexo 配置。
- 保留现有导航链接和 URL，不影响站点路由。
- 若重写后出现兼容问题，可回滚 `header.ejs` 与 `custom.styl` 中本次导航相关改动。

## 六、影响范围

直接影响：

- 全站桌面端顶部导航栏。
- 全站移动端顶部导航栏。
- 全站移动端菜单展开面板。
- 主题切换按钮在导航区域中的呈现。

间接影响：

- 首页、归档页、文章页等页面顶部可视区域的整体视觉感受。
- 移动端菜单打开时页面滚动行为。

不应影响：

- 文章内容渲染。
- 归档、分类、标签、分页数据。
- 页面 URL。
- Hexo 构建流程。

## 七、风险评估

- 顶部导航是全站公共组件，若样式选择器过宽，可能影响页面内其他 `.menu`、`.container`、`a` 元素。
- 如果模板结构变化过大，现有 `script.js` 中主题切换逻辑可能需要同步适配。
- 如果移动端菜单锁定滚动处理不当，可能导致关闭菜单后页面滚动状态异常。
- 如果桌面端与移动端共用结构处理不当，可能在断点附近出现布局拥挤或链接换行。
- 当前工作区已有多项未提交改动，本次开发需要只围绕顶部导航处理，避免误改或回退其他需求成果。

## 八、测试重点

- 执行 `npm run build`，确保 Hexo 构建通过。
- 桌面端验证：
  - 顶部导航显示正常。
  - 所有导航链接可见且不换行溢出。
  - 主题切换按钮可用。
  - hover/focus 状态清晰。
- 移动端验证：
  - `360px`、`390px`、`414px` 宽度无横向溢出。
  - 菜单按钮可打开菜单。
  - 关闭按钮可关闭菜单。
  - 菜单打开后链接排列整齐、可读、点击区域足够。
  - 菜单关闭后页面恢复正常滚动。
  - 深色/浅色主题下导航与菜单均可读。
- 回归验证：
  - 首页、归档页、文章页至少各检查一个页面。
  - 桌面端与移动端断点切换无明显闪烁或布局残留。
