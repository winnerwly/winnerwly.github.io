# 项目文档目录

本目录用于统一存放项目开发相关文档。所有开发相关文档必须使用中文编写，并遵循“先分析、再文档、经确认、后开发、再总结”的强制流程。

## 目录结构

```bash
docs/
  requirements/
    需求分析与开发前确认文档
  changes/
    变更说明、技术方案补充、过程调整记录
  reviews/
    开发完成后的总结与回顾文档
```

## 文档语言要求

所有需求分析、技术方案、变更说明、开发总结、测试说明、接口说明、架构设计以及 AI 工具生成的开发文档，都必须使用中文编写。

专有名词、代码字段、接口字段、命令、配置项、文件路径、变量名、函数名等技术内容可以保留原文，例如 `npm run build`、`AGENTS.md`、`docs/requirements/`。

## 开发前文档要求

每个需求或变更在开发前必须先在 `docs/requirements/` 下创建开发文档，内容至少包含：

- 需求背景；
- 需求目标；
- 需求范围；
- 现状分析；
- 技术方案；
- 影响范围；
- 风险评估；
- 测试重点；
- 确认记录。

确认记录必须写明确认人、确认时间和确认结论。未经确认，不允许进入开发。

## 开发过程要求

开发过程中必须严格按照已确认的开发文档执行。如需求范围、技术方案、接口结构、页面交互、权限逻辑、数据结构或风险点发生变化，必须暂停开发，更新文档并再次确认。

## 开发后总结要求

开发完成后，必须在 `docs/reviews/` 下创建中文开发总结，回顾原开发文档并说明：

- 本次完成内容；
- 与原开发文档的对照；
- 影响范围回顾；
- 测试情况；
- 遗留问题；
- 经验总结。

未输出开发总结的需求，不视为完整交付。
